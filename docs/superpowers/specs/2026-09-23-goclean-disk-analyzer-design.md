# Дизайн-документ: GoClean — Параллельный анализатор дискового пространства и очиститель кэша

**Дата:** 2026-09-23  
**Проект:** GoClean  
**Язык:** Go (1.27+)  
**Целевая платформа:** Кроссплатформенный (Windows, macOS, Linux)

---

## 1. Обзор и цели

**GoClean** — это высокопроизводительный дисковый анализатор и утилита очистки, объединяющая:
1. **Параллельное ядро на горутинах**: параллельный обход дерева каталогов с помощью адаптивного пула воркеров (`runtime.NumCPU() * 2..4`), распределяющий чтение метаданных по всем доступным ядрам процессора.
2. **Гибридный интерфейс**:
   - **CLI-режим по умолчанию (в стиле `dust`)**: красивое дерево директорий, процентные полосы заполнения на псевдографике (`[████████░░░░] 68%`), подсветка тяжелых каталогов и кэшей с тегом `[CACHE]`.
   - **Интерактивный TUI-режим (`-i` / `browse`, в стиле `ncdu`)**: полноэкранный терминальный интерфейс на базе `charmbracelet/bubbletea` и `lipgloss` с быстрой навигацией (стрелки, Enter, Esc), сортировкой, поиском и удалением папок прямо на месте.
3. **Детектор и безопасная очистка кэшей**: автоматическое обнаружение `node_modules`, `target`, `.cache`, `.next`, `.venv`, `__pycache__`, `build`, `dist` и безопасное удаление (с подтверждением или в режиме `--dry-run`).

## 3. Детали компонентов

### 3.1. Структура дерева (`internal/model/node.go`)

```go
type NodeType uint8

const (
    NodeTypeDir NodeType = iota
    NodeTypeFile
    NodeTypeSymlink
)

type Node struct {
    Name      string
    Path      string
    Size      int64       // Суммарный размер в байтах (агрегируется post-order)
    ItemCount int64       // Число вложенных файлов и папок
    Type      NodeType
    ModTime   time.Time
    IsCache   bool        // Флаг обнаружения как директория кэша
    CacheKind string      // Тип кэша (npm, cargo, python, etc.)
    Parent    *Node       `json:"-"`
    Children  []*Node
    mu        sync.Mutex  // Защита добавления дочерних элементов во время сканирования
}
```

- После параллельного заполнения листьев запускается функция `PostOrderAggregate(root *Node)`:
  размер каждого родителя вычисляется как сумма размеров всех непосредственных детей.
- Сортировка `SortChildren(sortBy SortCriteria)`: по размеру (по умолчанию), по имени или по количеству элементов.

### 3.2. Параллельный сканер (`internal/scanner`)

- **Конкурентная модель**:
  - Очередь директорий для сканирования: канальная очередь `taskQueue chan string` с буфером.
  - Адаптивное число воркеров: по умолчанию `runtime.NumCPU() * 2`, переопределяемое флагом `-w`.
  - Отслеживание окончания сканирования: атомарный счетчик `inFlight int64`. Инкрементируется при отправке директории в очередь, декрементируется после завершения `os.ReadDir` и добавления поддиректорий в очередь. Когда `inFlight == 0`, закрывается канал завершения.
  - Контекст `context.Context` с обработкой сигналов прерывания (Ctrl+C).
- **Сбор метаданных**:
  - Использование `os.ReadDir(dirPath)`.
  - Для обычных файлов из `os.DirEntry.Info()` извлекается размер и время изменения.
  - Поддиректории создаются как узлы типа `NodeTypeDir` и пушатся в очередь сканера.
- **Безопасность ссылок**:
  - `sync.Map` для посещенных путей (канонический путь через `filepath.EvalSymlinks`).
  - Символические ссылки на каталоги не обходятся рекурсивно, предотвращая бесконечные циклы.
- **Ошибки**:
  - `Permission Denied` / блокировки файлов не прерывают сканирование, а аккумулируются в `ScanStats.ErrorsCount`.

### 3.3. Детектор и очиститель кэша (`internal/cleaner`)

- **Паттерны кэшей**:
  - `node_modules`, `.next`, `.nuxt`, `.turbo`, `.pnpm-store` (Node / JS)
  - `target` (Rust Cargo)
  - `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.venv`, `venv` (Python)
  - `.gradle`, `build` (Java / Gradle / Kotlin)
  - `.cache`, `bin`, `obj` (Go / .NET / C++)
- **Защита от опасных удалений**:
  - Черный список корней: `C:\`, `/`, `/etc`, `/usr`, `/var`, `C:\Windows`, `C:\Program Files`, домашняя директория `$HOME` целиком.
- **Режимы удаления**:
  - **Dry-run (`--dry-run`)**: только подсчет и вывод списка путей и суммарного объема.
  - **Interactive**: запрос подтверждения с цветным списком и объемом.
  - **Force (`-y` / `--yes`)**: непосредственный вызов `os.RemoveAll`.

### 3.4. Визуализация и CLI-интерфейс (`internal/ui`)

- **Форматирование полос (`bar.go`)**:
  - Генерация полосы шириной `N` символов (напр., 10-25 символов).
  - Использование символов `█`, `▌`, `░`.
  - Цветовая дифференциация: зелёный (<15%), желтый (15-40%), оранжево-красный (>40%).
- **CLI-вывод (`cli.go`)**:
  - Иерархическое дерево с ветвями (`├─`, `└─`, `│ `).
  - Сортировка по размеру.
  - Параметр глубины отображения (`-d / --depth`, по умолчанию 2 уровня).
  - Сводный блок со временем сканирования, числом файлов и объемом найденного кэша.

### 3.5. Интерактивный TUI-режим (`internal/ui/tui`)

- Реализация интерфейса `tea.Model` из `charmbracelet/bubbletea`.
- Поддержка горячих клавиш:
  - `↑` / `k`, `↓` / `j`: перемещение по списку.
  - `Enter` / `→` / `l`: проваливание в выбранную директорию.
  - `Esc` / `←` / `h`: переход на родительский уровень.
  - `s`: циклическое переключение сортировки (размер -> имя -> элементы).
  - `/`: быстрый поиск/фильтр по имени.
  - `c`: окно очистки всех найденных кэшей в текущей папке.
  - `d`: удаление выбранного элемента с подтверждением.
  - `q` / `Ctrl+C`: выход.
- Модальное окно подтверждения удаления с четкой цветовой индикацией и объемом.

## 4. Стратегия тестирования и верификация

1. **Юнит-тесты (`go test -v -race ./...`)**:
   - `internal/scanner/scanner_test.go`: создание временных директорий с фиксированными размерами файлов, запуск с разным количеством воркеров (1, 4, 8), проверка суммарного размера и детекции гонок.
   - `internal/cleaner/detector_test.go`: проверка правил сопоставления путей с кэшами.
   - `internal/cleaner/cleaner_test.go`: проверка безопасного удаления и запрета удаления корня.
   - `internal/ui/bar_test.go`: тестирование точности и форматирования полос заполнения.
2. **Бенчмарки**:
   - Тест производительности сканера на директории с 10 000+ файлами.
3. **Интерактивная проверка**:
   - Тестовый запуск утилиты в тестовой директории с `node_modules` и `target`.
   - Проверка флагов `--dry-run`, `-i`, `-w`, `--clean-cache`.
